# ADR 0008: The demo game is a project folder of data, and a test of the engine

Date: 2026-09-29. Status: accepted.

## Context

The first prototype was compiled into the editor and the player: a C++ generator wrote its level,
and `registerAllModules` linked its rules into every tool. That made the engine look like a
one-game project and hid whether the editor could really author a level.

## Decision

- `YK-DemoGame/` is a plain project folder (scenes, prefabs, assets, `project.ykproj`) that the
  engine consumes like any other project. It contains no C++.
- The generic rules the demo needs (win/lose, restart, next scene, a HUD's variables) live in the
  gameplay library as `LevelFlow`; everything else is authored from the standard components.
- Its art is original and generated by Python scripts in `YK-DemoGame/tools/`; the generated files
  are checked in, so building and testing need no Python. The level and prefabs are written by
  scripts through the same file formats the editor saves, then canonicalized by `yk format`.
- A bot playthrough test (`demo`) plays the whole level through the real runtime with the real
  input actions and fails when it cannot be completed; the editor's UI scripts edit, play and
  export the same project.

## Consequences

Anything the demo needs that the editor cannot express is a gap in the engine, found by the
demo. The engine has no line that mentions the demo, and a grep for its names finds none.
